# 技术决策说明

## 选择 Vite + TypeScript + Phaser 的原因

第一版目标是快速搭建一个可运行的 HTML 游戏 Demo 空壳，并为后续横屏办公室点击反应玩法保留清晰的工程边界。Vite 启动快，配置轻，适合预制作阶段反复验证。TypeScript 能在对象 ID、配置结构和场景模块逐步增加时提供类型约束。Phaser 3 面向浏览器 2D 游戏，内置场景、画布、输入和资源加载能力，适合后续实现桌面浏览器中的 1280x720 横屏 Demo。

## 第一版为什么不使用 Godot Web

当前目标是 HTML Demo 的预制作工程搭建，不需要完整编辑器工作流，也不需要提前引入引擎导出、Web 包体和运行时差异。使用 Phaser 可以直接在前端工程中推进场景、配置和资产替换流程，降低第一版验证成本。

## 第一版为什么不做复杂骨骼动画

设计方向强调低饱和、简化、可读的办公室横截面视觉。第一版只需要验证工程结构和画布运行，不需要角色复杂动作。复杂骨骼动画会提高资产制作、运行时接入和调试成本，也会过早扩大工程范围。

## 第一版为什么允许 SVG 和 AI 生成图并存

SVG 适合制作界面图标、可交互物件和简单矢量占位。AI 生成图适合探索办公室背景、人物气质和氛围草图。两者并存可以服务不同素材阶段：SVG 保持结构清晰，AI 生成图用于视觉探索与筛选。最终接入时应统一命名、尺寸和配置引用方式。

## 工程约束

- 不接后端。
- 不做存档。
- 不做移动端适配。
- 不做复杂动画系统。
- 不实现资源衰减、动作系统、QTE、领导巡查等正式玩法。
- 第一版面向桌面浏览器。
- 画布固定为 1280x720，16:9 横屏。

## 素材替换约束

后续素材替换不得改变对象 ID 和配置结构。美术资源可以迭代文件内容、视觉风格和处理版本，但程序侧引用的对象 ID、配置字段和目录语义需要保持稳定，避免素材替换影响玩法配置和场景布局。
