# 美术资产策略（ASSET_PLAN）

本文档确定《假装正在工作》Demo 的美术资产制作分工：哪些资产用 SVG/Canvas 制作，哪些用 AI 生图制作，AI 生图的能力边界在哪里，以及资产从生成到正式接入代码的入库流程。

来源文档：

- docs/STYLE_GUIDE.md（视觉风格规范，所有资产都必须遵守）
- docs/SCENE_LAYOUT.md（画面层级、对象布局、UI 区域坐标）
- docs/INTERACTION_FLOW.md（资产对应的交互触发时机）
- src/data/sceneObjects.json（已固化的对象 id、坐标与交互属性）
- src/data/visuals.json（objectId + state → assetId 映射，渲染层素材索引）
- docs/TECH_DECISION.md（"第一版为什么允许 SVG 和 AI 生成图并存"、素材替换约束）

本文档只确定资产策略与入库规则，不写正式玩法逻辑、不实际调用生图工具、不生成复杂成品插画。

---

## 1. SVG / Canvas 负责的内容

以下内容全部使用 SVG 或 Canvas 矢量绘制，不使用 AI 生图：

- 交互物件（电脑、键盘、手机、外卖盒、咖啡杯、文件堆/夹板等场景中可点击或承载点击物件的桌面道具）
- UI 组件（顶部状态栏、底部提示栏、领导警报 HUD、电脑弹层框架、同事气泡菜单、结束面板等）
- 图标（电脑页签图标、同事气泡图标等）
- 资源条（精神值、饱腹值、信任值三条资源条的图形表现）
- QTE 高亮（当前目标物件的描边发光效果）
- 危险状态标记（物件叠加的危险视觉标记，如手机亮屏、外卖摊开、桌面混乱提示）
- 简笔角色基础形象（主角、同事、领导剪影的静态状态图）

选择原因：这些内容需要精确的尺寸、稳定的颜色一致性，并且需要在程序里被频繁状态切换（hover/danger/QTE 高亮/错误红闪），矢量图形天然支持无损缩放、颜色变量化和程序化样式叠加，AI 生图无法满足这种精确性与一致性要求（见 docs/TECH_DECISION.md "第一版为什么允许 SVG 和 AI 生成图并存"）。

---

## 2. AI 生图负责的内容

以下内容使用 AI 生图制作，经筛选与处理后入库：

- 办公室横版背景概念图（用于风格探索与方向验证）
- 最终办公室背景底图（正式接入游戏的背景层）
- 开始页背景
- 结束插画（四种结束陈述各自对应的配图）
- 气氛图（用于验证领导压力等氛围基调的参考图）
- 风格探索图（用于在批量生成前对齐描边、色块、人物简化程度的参考图）

选择原因：这些内容是大面积的氛围背景或一次性插画，不需要被点击判定、不需要程序化状态切换，且依赖更丰富的环境细节与构图变化，适合用 AI 生图做风格探索与最终底图生产，比手绘矢量更高效（见 docs/TECH_DECISION.md）。

---

## 3. AI 生图不负责的内容

以下内容明确不使用 AI 生图，必须用 SVG/Canvas 制作，原因逐项说明：

| 不适用内容 | 原因 |
|---|---|
| 需要精准点击的 hitbox | AI 生图无法保证物件边界与程序里定义的 hitbox 坐标（见 `docs/SCENE_LAYOUT.md` 第 4 节）严格对齐，矢量图形可以按坐标精确绘制。 |
| 小尺寸 UI 图标 | AI 生图在小尺寸下细节失真、风格不稳定，且难以保证一组图标的视觉统一性，矢量图标可以共享同一套描边/色块规则。 |
| 资源条 | 资源条需要按数值精确拉伸/裁切（程序根据当前资源值渲染对应长度），AI 生成的静态图片做不到这种程序化形变。 |
| QTE 高亮 | QTE 高亮需要随时绑定到任意目标物件、跟随其形状描边并呼吸缩放，是一种程序化样式而非固定图片。 |
| 需要一致性的多帧角色动画 | 本 Demo 不做复杂人物动作（见 docs/STYLE_GUIDE.md 第 4 节），AI 生图也无法保证同一角色跨帧的形态、配色完全一致。 |
| 任何带可读文字的 UI | AI 生图模型生成可读文字的稳定性差，容易出现乱码或风格不统一的文字，所有需要文字的 UI（提示栏、按钮文案、电脑文档/表格内容等）必须用代码渲染真实文字或矢量排版，不嵌入 AI 生成的文字图层。 |

## 4. 入库规则

资产从生成到正式接入代码，统一遵循以下目录流程：

### 4.1 AI 生成图片流程

```text
生成原图        → assets/ai_generated/raw/
↓ 筛选
筛选后的图       → assets/ai_generated/selected/
↓ 裁切 / 压缩 / 调色
可用图           → assets/ai_generated/processed/
↓ 登记
正式接入代码     → 在 src/assets.ts 中登记引用
```

说明：

- `raw/` 保留所有候选原图，不做任何修改，方便追溯生成参数与对比。
- `selected/` 只保留通过筛选标准（见 `docs/AI_IMAGE_PROMPTS.md` 各资产的"筛选标准"字段）的候选图，可能仍是多选 1 的状态。
- `processed/` 是裁切、压缩、调色之后真正可以被代码引用的最终文件，文件名与 `assetId` 一致。
- 仅作风格参考、不直接入游戏的资产（如风格探索图、氛围参考图）止步于 `selected/`，不进入 `processed/`，详见 `docs/AI_IMAGE_PROMPTS.md` 对应条目的"是否可直接入游戏"字段。

### 4.2 SVG 资产分类目录

| 目录 | 内容 |
|---|---|
| `assets/svg/interactables/` | SVG 交互物件（电脑、键盘、手机、外卖盒、咖啡杯、文件堆等），以及承载这些物件的桌面/工位底图（桌子、同事桌子，因其功能定位与其他场景道具一致，归入同一目录） |
| `assets/svg/characters/` | SVG 角色（主角各状态、同事各状态、领导剪影） |
| `assets/svg/ui/` | SVG UI 组件（资源条、提示栏、HUD、弹层框架、按钮、气泡图标等） |
| `assets/svg/effects/` | SVG 特效（QTE 高亮、错误红闪、危险状态标记，以及"可选气氛资产"中决定用矢量制作的背景装饰元素，见 4.4） |

### 4.3 代码登记规则

任何正式接入代码的图片（无论来自 SVG 还是 AI 生图流程）**必须**在 `src/assets.ts` 中登记。`src/assets.ts` 已存在并维护，登记时只更新资源的文件路径引用，遵循 `docs/TECH_DECISION.md` 的"素材替换约束"。

三层素材职责分工：

- `src/data/sceneObjects.json`：只管对象 id / 坐标 / hitbox / 交互属性 / 视觉状态枚举；
- `src/assets.ts`：只管 assetId → 文件路径；
- `src/data/visuals.json`：负责 objectId + state → assetId 映射，渲染层只读它。

`placeholderAsset` 字段已从 `sceneObjects.json` 移除（原字段随素材路径机制迁移至 `visuals.json`）。

### 4.4 关于"可选气氛资产"的制作方式说明

`docs/ASSET_LIST.md` 第 D 类"可选气氛资产"（墙面海报、远处同事剪影、会议室门、走道阴影、荧光灯叠加效果）未被用户指定为 AI 生图或 SVG。出于以下原因，本计划将这一类资产统一规划为 **SVG/Canvas 制作**，而不是 AI 生图：

1. 这些内容是叠加在主背景之上的小型装饰元素或全屏光效叠加层，不需要 AI 生图擅长的丰富环境细节，反而需要和交互物件、UI 一样保持扁平、克制，避免"高细节插画污染交互可读性"（见 docs/STYLE_GUIDE.md 关键词）。
2. 其中 `fluorescent_light_overlay`（荧光灯叠加效果）本质是一个全屏光效叠加层，与画面边缘变暗、QTE 高亮一样属于程序化效果，而不是静态插画内容，更适合用 Canvas/SVG 渐变实现。
3. 这类资产标记为**可选**，优先级低于 A/B/C 三类核心资产，Demo 验收不依赖这些资产是否完成。

## 5. 分工总览表

| 资产类别 | 制作方式 | 目录 | 是否核心 |
|---|---|---|---|
| 交互物件 | SVG/Canvas | `assets/svg/interactables/` | 核心 |
| 角色（主角/同事/领导） | SVG/Canvas | `assets/svg/characters/` | 核心 |
| UI 组件 | SVG/Canvas | `assets/svg/ui/` | 核心 |
| 特效（QTE 高亮/红闪/危险标记） | SVG/Canvas | `assets/svg/effects/` | 核心 |
| 背景 / 开始页 / 结束插画 / 氛围图 / 风格图 | AI 生图 | `assets/ai_generated/{raw,selected,processed}/` | 核心（结局插画与风格/氛围参考图见各自资产说明） |
| 可选气氛装饰 | SVG/Canvas | `assets/svg/effects/` | 可选 |
