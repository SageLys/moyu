# 《假装正在工作》· 速览卡

### 项目定位

一个办公室题材的点击生存原型：你一边维持三条状态条，一边在领导巡查时把摸鱼留下的痕迹收拾干净——**做完并试玩之后，我们判断它没有潜力，停掉了。**

### 我的职责

我定义玩法目标、系统规则、交互取舍、配置口径与验收标准；AI 承担代码实现与位图候选生成。既然标准是我定的，设计不成立也是我的责任。

### 主线

**一个关于"假装在上班"的游戏，为什么玩起来只是在按提示点东西？**

- 我把摸鱼的代价做成一笔延迟结算的债：平时动作留下现场破绽，领导巡查时按优先级变成必须依次完成的操作。系统本身成立——但它的唯一产出，是给 QTE 生成一份待办清单。
- 我为它做了一个 33 项的实时调参面板，并用它调过一轮：把维持资源的操作占用率从 12.1% 拉到 59.3%。**"平时太空"是解决了，但压力曲线依然接不到平时段上**——占用率从第 1 波的 59.3% 一路走到第 6 波的 52.5%，反而更松。真正在变的只有 QTE。
- 于是全部张力都挂在 QTE 上，而 QTE 只能提供手眼协调，题材承诺的却是心理张力。**继续做只会得到一个办公室皮肤的节奏游戏，所以停。**

### 关键设计

- **不可撤销的破绽。** 5 个现场危险状态里有 3 个（`phone_lit`、`takeout_open`、`body_slack`）的 `clearedBy` 是空数组——玩家自己造的痕迹平时清不掉，只能在领导来的那几秒里还。
- **三个伪装层。** QTE 步骤按 `layer` 分为 `screen / desk / body`（1 / 3 / 2 个），对应"屏幕像在工作、桌面像在工作、人像在工作"。危险不足时用表演动作补齐，且这类清除是装饰性的——就算什么都没干，领导来了也得表演。
- **规则全部数据化 + 实时调参。** 10 个 JSON 配置、`tools/validate-config.mjs`（376 行）做引用完整性校验；`src/core/tuning.ts` + `src/ui/TuningPanel.ts`（合计 310 行）把 33 项玩法数值做成滑块，改完下一帧生效，可一键导出回填。

### 代表性迭代

用调参面板做过一轮实测调整：三条资源衰减率从 −0.25 / −0.20 / −0.15 提到 −0.70 / −0.55 / −0.45（约 2.8–3.0 倍），前三波巡查间隔从 35 / 32 / 28 秒压到 24 / 22 / 20 秒。
**维持三条资源的操作占用率因此从 12.1% 涨到 59.3%，平均点击间隔从 8.24 秒缩到 1.69 秒。**
但六个波次的占用率仍然不随难度上升——12.1%→11.7% 变成了 59.3%→52.5%，两版都在往下走。**结构问题没被这轮调参碰到。**

### 完成度与限制

本地可完整游玩的单局原型，`validate` / 单测 / 构建 / 冒烟四件套全绿。
**限制要主动说清**：有多人试玩并据此判断核心机制无聊，但**没有留下任何书面试玩记录**；没有遥测、没有参数实验、没有对照组；数值的首版起点来自一份建议表，我只调过一轮、从没回头验算过那个起点；无外部可访问的 Demo 部署（若已部署，见文末 Demo 入口）。
本文所有推算数字来自 `docs/portfolio/verify/steady_state.mjs`，可现场重跑。
