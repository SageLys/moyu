# 美术风格规范（STYLE_GUIDE）

本文档是 HTML Demo 美术资产预制作的第一份产出，确定《假装正在工作》的整体视觉风格基调，供后续 `docs/ASSET_PLAN.md`、`docs/ASSET_LIST.md`、`docs/AI_IMAGE_PROMPTS.md` 与正式美术制作引用。

来源文档：

- 《假装正在工作》Demo 制作方案.md（第 5 节：画面风格）
- 假装正在工作_文案风格定稿说明.md（语气基调，用于推导视觉氛围的"克制"原则）
- docs/SCENE_LAYOUT.md（画面层级、UI 区域坐标）
- docs/INTERACTION_FLOW.md（QTE 高亮、错误反馈、领导压力的触发时机）
- src/data/sceneObjects.json（已固化的 `qteHighlightStyle`、`wrongClickFeedback` 颜色与时长数值）

本文档只定义视觉风格方向与规范，不写正式玩法逻辑、不实现代码。

---

## 0. 一句话风格定位

**低饱和设计配色下的极简荒诞职场 Flash 卡通风。**

办公室是一个被压平成横截面的小舞台，物件比人更重要、比人更精细；人物只是站在舞台上的简笔记号。

---

## 1. 关键词

| 关键词 | 说明 |
|---|---|
| 粗描边 | 所有交互物件与角色轮廓使用统一的粗描边，让物件在低饱和背景前依然清晰可辨。 |
| 扁平色块 | 不使用渐变、光影贴图或材质纹理，颜色以纯色块平铺为主。 |
| 低饱和配色 | 全局色彩饱和度压低，避免任何鲜艳、刺眼的大面积颜色。 |
| 强可读性物件 | 凡是玩家需要点击或需要识别状态（安全/危险）的物件，造型与颜色必须第一眼可辨认，不能因为风格化而牺牲可读性。 |
| 极简夸张人物 | 主角与同事使用简笔卡通小人，比例略夸张、头部稍大，不追求解剖准确。 |
| 办公室横截面舞台感 | 整体场景按舞台布景思路设计：背景、中景、人物与道具分层明确，像被切开的办公室剖面。 |
| 轻松滑稽但带压迫感 | 默认状态轻松滑稽，领导巡查靠近时通过暗角、HUD、阴影叠加压迫感，两种情绪要能快速切换而不冲突。 |
| 比火柴人精细一点 | 人物精细度的上限参照：比纯火柴人多一点点轮廓细节（头型、四肢粗细、坐姿轮廓），但远低于完整卡通角色设计的精细度。 |
| 避免写实人物 | 不画真实比例、真实材质、真实面部细节的人物，主角与同事全程保持卡通简化形态。 |
| 避免复杂纹理 | 不使用布料褶皱、木纹、磨砂玻璃反光等细节纹理，所有材质都用纯色块 + 描边表达。 |
| 避免高细节插画污染交互可读性 | 任何美术资源（尤其是 AI 生图背景）都不能比交互物件更精细、更抢视觉焦点，否则会让玩家分不清哪些是可以点的。 |

## 2. 颜色方向

### 2.1 基础色板（建议起点，可在实现阶段微调，但必须维持低饱和、灰蓝/米灰基调）

| 用途 | 颜色方向 | 建议色值（起点） |
|---|---|---|
| 办公室背景主色 | 灰蓝 | `#9AAAB5` ~ `#C3CDD4` |
| 办公室背景辅色 | 米灰 | `#E3DCCF` ~ `#D8D0C0` |
| 背景点缀色 | 低饱和绿色 | `#92AE8E` |
| 背景点缀色 | 低饱和橙色 | `#D6A06B` |

### 2.2 交互物件配色规则

- 交互物件（电脑、键盘、手机、外卖盒、咖啡杯、文件堆等）颜色对比度要**比背景稍高**，确保第一眼能从背景中跳出来。
- 同一物件的"安全态"与"危险态"用色块差异区分（例如手机熄屏用冷灰，手机亮屏叠加更亮的屏幕色块），不依赖复杂图标。
- 建议交互物件起点色板：电脑深灰蓝 `#5C7A8A`、键盘暖灰 `#C9BFAE`、手机蓝灰 `#6E8B9E`、外卖盒暖橙 `#D98E4F`、咖啡杯棕 `#8B5E3C`、文件堆米白 `#E8E2D6`。

### 2.3 状态反馈配色（已与 `src/data/sceneObjects.json` 固化数值对齐，不得擅自更改色值）

| 状态 | 颜色 | 数值来源 | 说明 |
|---|---|---|---|
| QTE 高亮 | 明显但不刺眼的琥珀橙 `#FFB000` | `sceneObjects.json.qteHighlightStyle.strokeColor` | 描边 4px + 发光 + 1.2s 呼吸缩放（`scale 1.00-1.05`），不用纯红或纯黄，避免与错误反馈、领导 HUD 混淆。 |
| 错误点击反馈 | 红闪 `#FF3B30` | `sceneObjects.json.wrongClickFeedback.flashColor` | 仅闪烁约 0.18 秒（`flashDurationSec`），不长期覆盖画面，闪完即恢复物件原色。 |
| 领导压力 HUD / 暗角 | 低饱和红色 + 深灰蓝阴影 | 制作方案第 13.3、14.7 节 | 暗角使用低饱和深蓝灰，红色只作 HUD 边框或细节点缀，不大面积铺色，避免喧宾夺主。 |

### 2.4 配色禁忌

- 不使用高饱和荧光色（除 QTE 高亮、错误红闪这两个明确定义的状态色，且二者都做了"短时/局部"限制）。
- 不使用纯黑、纯白作为大面积底色。
- 领导压力阶段不得让红色覆盖整个画面或长时间停留，必须保持"克制"，呼应文案风格的冷静基调。

## 3. 线条规则

| 规则 | 说明 |
|---|---|
| 交互物件粗描边 | 默认状态描边建议 2–3px，QTE 高亮态固定使用已定义的 4px（`strokeWidthPx`），保持物件轮廓清晰可点。 |
| 人物轮廓清晰 | 主角与同事的描边粗细与交互物件同级或略粗，确保人物在背景前不会被物件或背景盖过视觉权重。 |
| 背景线条弱于交互物件 | 背景（远处走道、墙面、地板）的线条要更细，或干脆只用色块分区不描边，避免背景细节抢夺前景交互物件的注意力。 |
| UI 线条干净，不仿真 | UI 组件（资源条、提示栏、弹层、按钮）使用纯色块 + 简洁描边，不模拟真实操作系统或真实软件的渐变高光、阴影投影、拟物玻璃质感。 |

## 4. 动画原则

1. **不做复杂人物动作。** 主角与同事不做骨骼动画、不做逐帧动作序列，不追求动作流畅性。
2. **用以下手段表现状态变化，而不是靠人物动作：**
   - 缩放（如 QTE 高亮的 1.00–1.05 呼吸缩放）
   - 抖动（如错点 QTE 目标时倒计时轻微抖动、资源下降时资源条抖动）
   - 闪光（如点击成功闪一下、错误点击 0.18 秒红闪）
   - 透明度（如资源条发亮/转暗、安全窗口期的提示渐隐）
   - 描边（如 hover 描边、QTE 高亮描边）
   - 屏幕暗角（如领导预警与检查阶段画面边缘变暗）
3. **主角和同事只需要少量状态图，或可由程序在少量状态间切换表情/姿态：**
   - 主角：`protagonist_idle`（默认坐姿）、`protagonist_slack`（人体不像工作的危险姿态）、`protagonist_sit_up`（QTE 坐直后的修正姿态）。
   - 同事：`coworker_idle`（默认状态）、`coworker_watch`（望风时望向走道）、`coworker_unstable`（同事精神值低档的异常细节）。
   - 不为这些状态制作过渡动画补帧，状态切换以直接替换静态图或简单交叉淡入淡出实现。
